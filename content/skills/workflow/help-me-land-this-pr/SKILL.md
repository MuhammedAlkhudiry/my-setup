## Workflow

1. Explain the PR's purpose, technical decisions, and trade-offs. Distinguish recorded reasons from inferred ones.
2. Summarize the current implementation, review feedback, checks, and merge status.
3. Identify blockers and what each needs to be resolved.
4. Perform $code-review and guide the user through the important changes, decisions, and findings.
5. If no hard blocker or pending user decision prevents progress, babysit the PR until it is mergeable or needs an external action.
6. Use $implementation-walkthrough to guide QA and preserve progress.
